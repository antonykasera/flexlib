# flexlib bench

Firmware that times every flexlib function on the board, next to newlib libm,
libgcc's soft-float and CMSIS-DSP built with the same flags. Results:
[docs/results/f103.md](../docs/results/f103.md).

```
core/        bench.h (the case macros), bench_core.c (timing, golden check,
             groups), golden.c (generated by `make golden`), golden_gen.c
cases/       cases_<module>.c: one file per library module, with its
             candidates and baselines; cases_cmsis.c for CMSIS-DSP's
port/f103/   main.c (clock, USB CDC report), cache_probe.c, linker.ld
```

## Running it

```sh
git submodule update --init          # third_party/flex and third_party/cmsis-dsp
make bench-run                       # flash and read each image, write the results
make bench-windows                   # the instructions each case times
make bench BENCH_SET=math            # one image: utils | math | struct | dsp | dsp2
```

`make bench-run` flashes over ST-Link, reads the report from the board's USB
CDC port (`BENCH_PORT`, default `/dev/ttyACM0`) and writes
`docs/results/f103.md`. Run `make golden` after changing a case or a kernel; CI
fails if `core/golden.c` is stale.

## Method

- One call per input, timed with the DWT cycle counter over 256 fixed inputs;
  min, median and max are reported. Counter read cost is subtracted.
- Warm: each case runs once untimed first. Cold: the flash cache is flushed
  before every sample; cold numbers move by about one line (113 cycles).
- The board is an F103 clone (CPUID 0x412FC230) whose flash behaves like a
  cache (32-byte lines, 16-32 KB). A genuine STM32F103 has none, so timings
  may differ, especially for tables and rarely run code.
- Built at `-O2` without LTO, so library functions are timed as real calls.
- `make bench-windows` lists the instructions inside each timed window.
- Each case's output hash on the board is checked against the same code run
  on the host.
- Any non-empty window reads one cycle high; the `empty, int16 arg` row
  measures it.
- Samples above 2 x median + 4 are counted and listed by input index.
- "Flash read cost" measures the board's flash per load, cold and warm.
- Five images: flexutils, flexmath's scalar functions, its structures, and
  flexdsp in two.
  The largest needs about 92 KB of flash (`st-info --probe` shows yours).

## Adding a case

Write it with `BENCH_UNARY` / `BENCH_BINARY` (or `_COLD`) in
`cases/cases_<module>.c` (see `core/bench.h`), list it in that file's
`cases[]`, add a new file to `BENCH_CASES_<set>` in `mk/bench.mk` and its group
to `core/bench_core.c`, then `make golden`. Use `BENCH_CALL` for candidates
timed as calls.
